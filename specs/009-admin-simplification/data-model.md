# Data Model: 管理画面の整理

保存するデータ（D1 の表と列）と、サーバーの API の形は変えない。この整理で新しくできるのは、管理画面が描画のたびに導く値だけ。

## 店舗の枠の判断（`StoreResources`）

`admin-app/src/lib/store-resources.ts` の `resolveStoreResources(resources, storeId, selectedId)` が返す。

| kind | いつ | 持つもの | 画面での扱い |
| --- | --- | --- | --- |
| `unknown` | 設定のデータが無い（読み込み中・取得失敗）、または店舗が未決定 | `resourceId: ""` | 欄も案内も出さない。保存させない |
| `none` | 店舗の稼働中の枠が 0 | `resourceId: ""` | 未設定の案内を出す。保存させない |
| `single` | 稼働中の枠がちょうど 1 つ | `resource`、`resourceId`（その枠） | 欄とリソース名を出さない。その枠で保存する |
| `multiple` | 稼働中の枠が 2 つ以上 | `resources`（稼働中の枠）、`resourceId`（選んだ値が候補にあるときだけ。それ以外は空） | 今どおり欄を出す。選ぶまで保存させない |

決まりは次のとおり。

- 稼働中とは、枠の `active` が真で、`storeId` が選んだ店舗と同じもの。
- `resources` に `undefined` を渡すのは、取得が成功していないとき。空の配列は「本当に 0 件」を意味する。
- 前の予約から次の予約を作るときに、停止中や別の店舗の枠が選ばれていても、`single` ならその店舗の稼働中の枠になる。`multiple` なら空になって選び直しになる。

## 作成パネルの有効な値

作成パネルは、利用者が選んだ値（state）をそのまま持ち、有効な値を描画のたびに導く。導いた値は state に書き戻さない。

- **有効な店舗**: 設定の店舗が 1 件ならその店舗、それ以外は選んだ店舗。
- **店舗の欄を出すか**: 設定の店舗が 1 件のときは出さない。設定の読み込み前は出す。
- **有効な枠**: 有効な店舗で `resolveStoreResources` を呼んだ結果の `resourceId`。
- **保存を止めるか**: 判断が `unknown` か `none` のとき。
- **予約経路の初期値**: `DEFAULT_CREATE_ORIGIN`（`walk_in`、表示名「店頭」）。初期値・リセット・変更の有無の判定で同じ定数を使う。

検査・送信・確認の画面・空き枠の取得には、有効な値を使う。送る形（`storeId`、`resourceId`、`origin` など）は今と同じ。

## LINE 友だちの紐付けで送る店舗

`admin-app/src/lib/link-store-id.ts` の `pickLinkStoreId(stores, selectedStoreId)` が返す。

- 画面の上で選んでいる店舗が設定の店舗にあれば、その id を返す。
- 無ければ（全店舗のとき）、設定の先頭の店舗の id を返す。
- 店舗が 0 件なら空を返す（今と同じく、紐付けの操作を無効にする）。

サーバーでは、この店舗は存在の確認と、操作の記録の詳しい情報にだけ使う。お客様は店舗に属さないので、紐付く相手は変わらない。

## 予約管理の表示する店舗

- 画面の上で店舗を選んでいる（店舗スタッフは常に自分の店舗）とき: 店舗の列・店舗での並べ替え・カードの店舗名を出さない。
- 全店舗のとき: 今どおり出す。

## 予約管理の状態の絞り込み

- 選択肢から「来店中」（`checked_in`）を外す。サーバーの状態と、一覧の印の表示（「来店中」の印）は残す。
- 保存された絞り込みの状態が選択肢に無いときは、保存値を使わず既定で開く。
