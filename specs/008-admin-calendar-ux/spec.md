# Googleカレンダーに近い予約画面・管理画面

依頼日: 2026-11-17。状態: 実装中（2026-11-19 にオーナーの決定を反映）。

調査基点: `3f65c69e64fd3999e415c83c14f5c6dfa928c13d`。対象リポジトリ: `ojungo69/reservation-line-homepage-source`。

## 目的

Googleカレンダーを使い慣れたスタッフが、スマホ、Mac、マウスで予定を見渡し、予約詳細・カルテまで移動できる管理画面にする。お客様向け予約画面も共通の文字、色、部品で整える。

オーナーは白いサイドバーのカレンダー案とカルテ案を選び、その後、Googleカレンダーに近い質感・配色と、指をスライドさせる操作を希望した。本仕様はこの選択を基準にする。

## ユーザーストーリー

### P1: 予定を指で見渡す

スタッフはスマホで時間軸を上下にスクロールし、左右スワイプで前後の日を確認する。Macでは2本指の上下で時間、左右で前後の期間を確認する。縦に閲覧しただけで日付が変わったり、予約が移動したりしない。

### P1: 予約とカルテを行き来する

スタッフは予約を選んで日時・メニュー・状態を確認し、カルテへ進む。戻ると同じ店舗・期間・位置から作業を続けられる。

### P1: 予約を誤って上書きしない

スタッフは予約の移動や施術時間の変更候補を確認して保存する。別のスタッフが先に変更した予約は、古い画面から上書きされない。通信結果が分からない場合も、通知を重複させる再操作をしない。

### P2: どの入力方法でも操作を完了する

利用者はスワイプやドラッグを使わず、ボタンと日時フォームだけで同じ業務を完了できる。キーボード、VoiceOver、TalkBackでも予約・状態・変更結果が分かる。

### P2: お客様が予約内容を把握する

お客様はメニュー、料金、日時、承認待ちの意味を確認し、既存の本人確認と3ステップを通って申し込める。施術時間をお客様向けに表示しない現行方針を維持する。

## 受け入れ条件

実装完了の判定には[受け入れ確認](quickstart.md)を使用する。主要な判定は次のとおり。

1. スマホで縦に閲覧し、左右へ日を送り、予約を開き、カルテへ進み、同じ位置へ戻れる。
2. Macの実トラックパッドで上下・左右・惰性・斜め入力・ピンチを試し、誤った期間移動と予約変更が起きない。
3. マウスとタッチの変更候補が同じ業務条件で検証され、保存前に変更と通知を確認できる。
4. 2つのセッションで同じ予約を変更した場合、古い版の保存を拒否し、他者の変更を上書きしない。
5. 保存結果が分からない通信切断で、重複通知や重複変更を発生させない。
6. ボタンとフォームだけでも作成・移動・時間変更・期間移動を完了できる。
7. 公開予約画面の表示とフォーム変更が、予約計算・本人確認・承認状態を変えない。
