# 実装後の受け入れ確認

この手順は将来の実装を確認するためのものです。今回の文書PRではアプリの操作試験・API試験・実機試験を実施していません。

## 1. 確認環境を記録する

実装PRのcommit SHA、端末、OSとブラウザの版、入力機器、通常タブまたはPWA、拡大率、テーマ、動きを減らす設定を記録します。Macではナチュラルスクロールとページ間スワイプの設定も記録します。

対象はiPhone Safari、受付のiPad Safariとホーム画面版、Android Chrome、Mac Safari・Chromeの実トラックパッド、マウス、キーボードです。ホーム画面追加・インストール表示も、製品で提供する場合はそれぞれ確認します。スマホのエミュレーションや合成wheelイベントだけで実機完了にしません。

## 2. 架空データを用意する

本番の顧客や通知先を使わず、隔離した検証環境に次を用意します。

- owner、system_admin、異なる店舗に所属するstaffのセッション。
- 複数のリソース、無効化されたリソースの既存予約、承認待ち、確定、来店済み、完了、取消の予約。
- 短い予約、同時刻の複数予約、占有5分の旧形式、施術235分と清掃5分の境界例。
- 休憩を挟む営業時間、臨時休業、営業時間外の既存予約、外部ブロック。
- 同一顧客、同一電話番号hashの別顧客、同一リソースで重なる変更候補。
- LINE対象・対象外の予約と、Google同期の待機・失敗を再現できるジョブのテスト代替。
- 月末、年末、今日と翌日をまたぐ閲覧状態。

画面の密度評価には、1店舗の週表示は営業時間を予約で埋めた週（1日20件前後）を、全店舗の日表示は4店舗とも同じ密度にした日を基準にします。実運用でこれを上回る場合は、観測した密度に合わせて増やし、件数を記録します。過剰予約を正常データとして作らず、重なり表示用の異常例は分けます。

## 3. スマホ・Macで閲覧する

[INT-14の試験表](interactions.md#int-14-受入試験と追跡表)を各環境で実行します。少なくとも次を確認します。

1. 予約カードの上から縦にスクロールし、日付や予約が変わらないことを確認する。
2. 遅い横スライドと速いフリックで、前後の1期間に移動することを確認する。
3. 閾値未満、斜め入力、方向反転、Macの長い惰性で、予定しない期間へ飛ばないことを確認する。
4. 店舗の列が横にあふれる日表示（全店舗）で列を端まで動かし、日付が変わらないことを確認する。ヘッダーの専用帯とボタンでは日付を変える。
5. 全店舗を選んだまま、広い画面で開く・保存した週表示を開き直す・狭い画面で開く・週表示のボタンと W キーで切り替える・店舗を1つ選ぶ、の 5 つを確かめる。見られる店舗が1つだけの利用者では、全店舗の案内が出ずに週表示へ進めることも確かめる。広い画面の初回と週の開き直しは日表示で開いて保存した選択を上書きしない。狭い画面の初回は予定一覧。週への切り替えでは店舗を選ぶよう案内する。店舗を選ぶと保存した週表示に戻る（狭い画面では日表示のまま）。
6. ピンチ、OSの端からの戻る操作、ブラウザ履歴、フォーム内スクロールを確認する。日付移動と履歴移動が同時に発生した場合は不合格とする。
7. 予約詳細からカルテへ進んで戻り、表示期間、位置、選択、フォーカスが復元されることを確認する。
8. 幅変更・画面回転・キーボード表示で、一覧の選択や編集中の入力を失わないことを確認する。

## 4. 予約変更を確認する

[予約変更契約](contracts/reservation-interactions.md)のAPI-01〜API-25を実行します。特に次は別々に記録します。

| ケース | 合格条件 |
|---|---|
| 空き範囲から新規予約 | 希望枠を引き継ぐ。メニューの正式な施術時間・料金を勝手に変更しない |
| 移動と下端リサイズ | 移動は占有時間維持。リサイズは開始・清掃5分を維持し、施術終了を変更する |
| 選択後のタッチハンドル | タップは選択と詳細表示（INT-07-01）、長押しは選択とハンドル表示（INT-07-02）で、どちらも変更候補を始めない。詳細を閉じた直後も同じ予約の選択とハンドルが残る。長押しした指をそのまま動かしても変更候補は始まらず、指を離した後に別のpointerdownでハンドルを押したときだけ始まる（INT-07-02、INT-07-04） |
| 無変更drop・キャンセル | 無変更dropではpreview・確認を開かない。確定前のキャンセルではcommit・通知を発生させない |
| pointercancel・追加指・blur・回転 | 仮表示を片付け、未送信の変更を保存しない |
| 別店舗・別リソース・外部予定 | 不許可のドロップを保存しない。フォームを使って権限を迂回しない |
| 2つのセッションによる変更 | 古いexpectedVersionを競合として拒否し、先に保存した内容を上書きしない |
| 同一枠への同時保存 | 予約行・ロック・通知・監査が原子的に成功または失敗する |
| preview後に他者が枠を確保 | previewを予約保証として扱わず、commitで競合を拒否する |
| 5分候補と変更後の長さ | 15分候補の有無だけで保存可能と判定しない。清掃を含めて再検証する |
| 送信後に応答を失う | 同じキー・同一payloadのreplayで照合し、二重通知しない。現在予約を過去のreplay結果へ戻さない |
| 予約保存成功、Google同期失敗 | 保存済み予約を保持し、Google反映待ち・失敗を別に表示する |
| 開始変更、施術時間だけの変更、pending移動 | 現行のLINE通知条件と承認状態を維持する |
| 変更を戻す | 逆変更もversion・権限・時刻・空き条件を確認し、必要な再通知を説明する |
| API未対応のバックエンド | 直接操作を有効にせず、旧writeへフォールバックしない |

開始を過去へ移す失敗と、開始時刻を維持した施術時間変更の成功を混同しません。既存予約の清掃込み占有と旧形式も契約に従って確認します。

## 5. 見た目と代替操作を確認する

- ライト・ダーク・systemで本文、予約、選択、警告、操作部品のコントラストを測定する。
- 320px、390px、768px、1440px付近とブラウザ200%拡大で、主要操作に到達できることを確認する。
- 短い予約を44pxへ引き伸ばして時間を歪めていないことと、独立した編集経路があることを確認する。
- VoiceOver・TalkBackで期間、予約の状態、確認内容、保存結果を確認する。
- キーボードのセル移動と、ボタン・フォームだけによる期間移動・予約変更を最後まで実行する。
- 動きを減らす設定で大きな横スライドが省略され、結果と選択が分かることを確認する。
- 透明度を下げる設定とコントラストを上げる設定で、上部バー・＋ボタン・開いた詳細が不透明になり、必要なグリッド線が見分けられることを確認する。
- お客様向け画面で施術時間非表示、料金、承認待ち、本人確認、入力エラー、固定フッターを確認する。
- iPad Safari とホーム画面版で、ぼかしが上部バー・＋ボタン・開いた詳細・引き出しとして開いたサイドバーだけにあり、常に出ているサイドバーとスクロール領域の中には無いこと、同時に 2 枚（詳細か引き出しを開いた間は 3 枚）を超えないことを確認する。
- 旧画面（日曜始まり）と新しい画面（月曜始まり）で、JST の日曜・月曜の境目の週表示と日付移動を確認する。
- 新しい画面の表示モードと密度が、再読み込み後も同じ端末で保たれ、別のブラウザーでは既定値になり、保存できない環境でも既定値で動くことを確認する。
- 切り替えがオフの環境（本番）で、今の予定表・顧客カルテ・外枠が変わっていないことを確認する。
- 確認用環境で `"true"` と `"false"` のどちらも承認済みの配備経路を通って届き、配備後の認証済みの `/me` に反映されること、明示の停止の後の通常の再配備でもオフが保たれることを確認する。

## 6. 追従と読み込みを測定する

指やポインターへの最初の視覚反応は100ms以内を目標にします。連続操作は60Hz端末でフレーム間隔の95パーセンタイル20ms以下を初期目標とし、測定器と条件を記録します。これは未測定の性能保証ではなく、試作の判定基準です。達成できない場合は原因と調整案を記録してから基準を見直します。

通信を遅くして、先読みなし・取得失敗・応答順序の逆転を確認します。ネットワーク待ちでもドラッグ候補の追従を止めず、未確認の候補を保存済みや確実な空きとして示しません。個人情報を性能計測ログへ出力しません。

## 7. 自動検証と結果を記録する

[READMEの開発時の確認](../../README.md#開発時の確認)と既存CIを実行します。旧画面のスケジュール・時間軸のテストは変えずに実行し、新しい画面と経路の試験を足します。サーバー側の予約変更、available-slots、冪等性のテストは必要な差分で拡張します。

結果には、対象commit、各UX・INT・API要件の合否、実機の画面録画または手順、性能値、未対応環境を記録します。合成イベントの成功と実機の成功を分けます。未検証の端末を対応済みとして扱わず、文書のチェックだけで実装Issueを閉じません。
