# 管理カレンダーの操作仕様

## INT-01 目的と規範

本書は、既存の予約管理Web/PWAで、スマホの指操作とMacのトラックパッド操作に対応するための提案仕様である。カレンダーの閲覧と予約の変更を区別し、閲覧中の指の移動で予約が変更されないことを優先する。

予約変更の検証・保存・結果照合は[予約カレンダー操作のAPI契約案](contracts/reservation-interactions.md)に従う。同契約のpreviewとversion条件付きcommitは未実装の提案であり、旧APIへ追加項目を送るだけで同じ保証を得たとは扱わない。

`MUST`は受入条件として必須、`SHOULD`は原則採用する推奨要件を示す。推奨要件を変更するときは、理由と実機確認結果を残す。要件IDは実装・テスト・不具合報告から参照する。

| 要件ID | 強度 | 仕様 |
| --- | --- | --- |
| INT-01-01 | MUST | 本書のジェスチャ、数値、確認画面は本アプリの設計として扱う。Google Calendarと完全に同じ挙動であるとは表示・説明しない。 |
| INT-01-02 | MUST | 期間移動は前後ボタンと日付選択でも実行できる。予約の作成、日時変更、時間の延長・短縮はフォームでも完了できる。 |
| INT-01-03 | MUST | 期間移動・選択・候補表示だけでは予約を保存しない。移動・リサイズは候補表示、preview検証、確認、version条件付きcommitの順で実行する。 |
| INT-01-04 | MUST | カレンダー内の操作領域を限定する。ページ全体、フォーム、ダイアログにカレンダー用の横スワイプ・wheel処理を適用しない。 |
| INT-01-05 | SHOULD | 期間移動でもスタッフの選択、絞り込み、表示時間帯の位置を保ち、同じ時間帯を比較できるようにする。 |
| INT-01-06 | MUST | 今回の予約変更は、保存済みの同じstore・同じresource内に限る。店舗・担当リソースは固定の確認情報とし、別店舗・別リソースへの移動を受け付けない。 |

## INT-02 表示モードと利用者の選択

「1表示期間」は、日表示では1日、週表示では1週、月表示では1か月、一覧表示では画面に明示した日付範囲を指す。常に表示中の範囲がヘッダーから分かるようにする。

| 要件ID | 強度 | 仕様 |
| --- | --- | --- |
| INT-02-01 | MUST | 狭い画面では、1日の時間軸、一覧、月を利用できる。7列の週表示を文字や操作領域が読めない幅まで縮めない。 |
| INT-02-02 | MUST | 旧`agenda`の一覧表示を選んでいる利用者の選択を保持する。新しい既定表示や名称の変更だけを理由に、時間軸へ強制変更しない。 |
| INT-02-03 | MUST | 保存した表示選択と、画面幅に合わせた一時的な表示を区別する。広い画面での週表示が狭い画面で1日表示へ切り替わっても、保存済みの週表示を自動で上書きしない。 |
| INT-02-04 | MUST | 一覧の前後移動は表示中の日付範囲と同じ単位で行う。一覧本文の縦スクロールは一覧閲覧に使用し、日付範囲を変える横操作はヘッダーの専用帯で行う。 |
| INT-02-05 | MUST | 月表示の日付タップはその日の予定を確認する操作とする。月セルの余白を時間枠として解釈して予約を作成しない。 |
| INT-02-06 | SHOULD | 月のセルには読み取れる件数・状態を示し、詳細は選択した日の時間軸または一覧で確認できるようにする。 |
| INT-02-07 | MUST | 表示変更後も、予約の詳細を開く、空き枠から作成する、フォームで日時を変更する操作を失わない。 |

## INT-03 操作領域と優先順位

同じ方向の入力に複数の意味を割り当てない。操作の開始位置を基準に、次の優先順位で担当を決める。次表の担当と優先順位はすべてMUSTとする。

| 優先 | 操作開始領域・状態 | 担当する操作 | 要件ID |
| --- | --- | --- | --- |
| 1 | 開いているフォーム、ダイアログ、日付選択、入力欄 | その要素の通常操作・スクロール | INT-03-01 |
| 2 | 選択した予約の専用移動・リサイズハンドル | 固定のstore・resource内で予約の開始位置・施術終了時刻を変更 | INT-03-02 |
| 3 | デスクトップでマウス・ペンを押した予約カード | 予約の移動候補（INT-06-04）。期間移動やresource列の横スクロールにしない。タッチでは予約カードも本文と同じ扱いで、選択後の専用ハンドルだけが変更を担当する（INT-07-04） | INT-06-04、INT-07-04 |
| 4 | 横にあふれるスタッフなどのresource列がある日表示の本文 | resource列の横スクロール、時間軸の縦スクロール | INT-03-03 |
| 5 | ヘッダーの日付移動専用帯 | 前後の表示期間への移動 | INT-03-04 |
| 6 | 横スクロールするresource列がない時間軸・月表示の本文 | 横は期間移動、縦は本文の通常スクロール | INT-03-05 |

| 要件ID | 強度 | 仕様 |
| --- | --- | --- |
| INT-03-06 | MUST | resource列が横にあふれる日表示では、本文の横入力を日付変更に使用しない。列の端に到達しても、同じ操作の続きを日付移動へ切り替えない。 |
| INT-03-07 | MUST | INT-03-06の画面では、日付変更をヘッダーの専用スワイプ帯、前後ボタン、日付選択から行えるようにする。専用帯はボタンのタップ領域と区別する。 |
| INT-03-08 | MUST | 操作開始後は担当領域を変更しない。操作途中で予約カードや別のスクロール領域を通過しても、担当を乗り換えない。 |
| INT-03-09 | MUST | 予約を変更するハンドル以外で、タッチ操作の移動開始を予約の移動・リサイズとして扱わない。 |
| INT-03-10 | SHOULD | ヘッダーの専用帯は、日付と前後ボタンの近くに配置し、初めて利用する人にも日付移動の場所が分かるようにする。 |

## INT-04 スマホの期間移動と時間軸閲覧

| 要件ID | 強度 | 仕様 |
| --- | --- | --- |
| INT-04-01 | MUST | 1本指の横スワイプで1表示期間だけ移動する。表示内容を左へ送る操作は次の期間、右へ送る操作は前の期間とする。 |
| INT-04-02 | MUST | 上下操作はブラウザの標準スクロールで時間軸を閲覧する。縦スクロール開始後に横揺れが生じても、その操作で日付を切り替えない。 |
| INT-04-03 | MUST | 操作開始直後の小さな移動では方向を確定しない。方向判定後は横または縦に固定し、同じ操作内で切り替えない。 |
| INT-04-04 | MUST | 横移動が確定距離に達して指を離した場合だけ、前後1期間へ移る。閾値未満・途中キャンセルでは元の期間へ戻る。 |
| INT-04-05 | MUST | 移動量が大きくても1操作で複数期間へ飛ばない。別の期間へ続けて移るには、指を離して新しい操作を開始する。 |
| INT-04-06 | SHOULD | 横操作中は内容が指に追従し、離した後に移動先または元の位置へ収まる。動きを減らす設定ではINT-12に従う。 |
| INT-04-07 | MUST | 2本目の指を検出したら、進行中の独自スワイプ・予約操作を中止する。通常のカレンダー本文ではブラウザのピンチ拡大を利用できるようにする。 |
| INT-04-08 | MUST | OS・ブラウザが画面端の操作を引き受けた場合は追従表示を取り消し、予約を変更しない。端操作をアプリが完全に制御できる前提にしない。 |
| INT-04-09 | SHOULD | 画面端の戻る操作と競合する端末では、端から始まる操作を独自の日付スワイプの開始対象から外す。対象幅は実機で確認する。 |

## INT-05 Macのトラックパッドとwheel入力

Macの2本指操作は、ブラウザが伝えるwheel・scroll入力として扱う。スマホの2つのタッチ点が届くことを前提にしない。

| 要件ID | 強度 | 仕様 |
| --- | --- | --- |
| INT-05-01 | MUST | カレンダー内の縦入力はブラウザの標準スクロールに任せ、時間軸を移動する。縦wheelを日付変更に変換しない。 |
| INT-05-02 | MUST | 期間移動を担当する領域の横入力は、連続したwheelを1操作にまとめて判定する。1操作につき最大1表示期間だけ移動する。 |
| INT-05-03 | MUST | 期間を1回切り替えた後は、同じ操作の慣性入力・方向反転・追加イベントで再度切り替えない。入力が止まり、新しい操作と判定できるまで再実行しない。 |
| INT-05-04 | MUST | `ctrlKey`付きのズーム入力を期間移動に使用しない。ブラウザのピンチ・拡大操作をページ全体で妨げない。 |
| INT-05-05 | MUST | 方向の意味は、内容が左へ移る入力が次の期間、右へ移る入力が前の期間とする。Macのナチュラルスクロール設定を変更させる前提にしない。 |
| INT-05-06 | MUST | 横にあふれるresource列、フォーム、ダイアログ、一覧本文ではINT-03の担当を優先する。横スクロールの端に達した後も、同じ入力列を日付変更へ流用しない。 |
| INT-05-07 | MUST | ブラウザがキャンセルできないwheel入力を日付切替とブラウザ履歴移動の両方として実行しない。競合が解消できない環境では、その領域の独自wheel切替を無効にし、前後ボタンと専用帯の別入力経路を維持する。 |
| INT-05-08 | SHOULD | wheelの生の差分だけで実際のスクロール方向を断定せず、ブラウザ設定とスクロール位置の変化を含めて方向を確認する。 |
| INT-05-09 | MUST | 通常のマウスホイール、トラックパッド、キーボードによる閲覧を混同しない。トラックパッドがなくても前後ボタンとフォームで全操作を完了できる。 |

## INT-06 タップ・クリックと予約作成

| 操作 | 結果 | 要件ID・強度 |
| --- | --- | --- |
| 予約のタップ・クリック | 予約を選択し、詳細を開く。 | INT-06-01 MUST |
| 時間軸の空き枠をタップ・クリック | その日・希望開始時刻を引き継いだ作成画面を開く。日表示では押した列の店舗とresourceも引き継ぐ。週表示では、表示中のresourceが1つの場合だけ店舗とresourceを既定値にし、複数の場合は作成画面で選ぶ。0の場合は空き枠から作成を開かず、表示する予定を選ぶよう案内する（作成ボタンからは開ける）。表示の絞り込みはresourceごとの空き判定に使わない。メニューに基づく正式な施術時間は作成画面で決定し、これだけでは保存しない。 | INT-06-02 MUST |
| デスクトップで空き範囲を押してドラッグ | 希望する開始・終了の範囲を仮表示し、離した後に作成画面へ引き継ぐ。店舗とresourceの引き継ぎはINT-06-02と同じ規則に従う。表示中のresourceが0の場合は、範囲を選んでも作成を開かず、表示する予定を選ぶよう案内する（作成ボタンからは開ける）。選択範囲は希望枠であり、メニューの正式な施術時間を変更・確定しない。 | INT-06-03 MUST |
| デスクトップで既存予約をドラッグ | 予約の移動候補を表示し、離した後にINT-09の検証・確認へ進む。 | INT-06-04 MUST |
| デスクトップで予約の下端ハンドルをドラッグ | 開始時刻を固定し、施術終了の変更候補を表示する。清掃5分は固定のまま施術終了に続けて描き、離した後にINT-09の検証・確認へ進む。 | INT-06-05 MUST |

| 要件ID | 強度 | 仕様 |
| --- | --- | --- |
| INT-06-06 | MUST | ドラッグ判定前の小さなポインター移動では、通常のタップ・クリックを失わせない。移動を伴わない押下だけで確認画面を開かない。 |
| INT-06-07 | MUST | スワイプ・ドラッグ終了後に発生するclickを、新規予約作成、詳細表示、確認画面の保存として重ねて処理しない。 |
| INT-06-08 | MUST | 移動は保存済みの占有時間をそのまま保つ。占有5分の旧予約も自動で延長しない。リサイズは開始時刻を固定し、施術終了を動かして`treatmentMinutes`だけを変更する。清掃5分は変更せず、施術終了と清掃込みの枠の終了を区別する。 |
| INT-06-09 | MUST | 候補の時刻刻み、最短時間、営業時間、担当者、設備・席数などの制約には既存の予約ルールを用いる。ジェスチャだけに別の許可条件を設けない。 |
| INT-06-10 | MUST | 移動不可・編集不可の予約では変更ハンドルを有効にしない。詳細から権限に応じた操作を提供する。 |
| INT-06-11 | SHOULD | ドラッグ中は候補の日付、開始、施術終了、清掃込みの枠の終了を読み取れる形で表示し、固定の店舗・resourceも確認できるようにする。指やポインターの直下だけに時刻を表示しない。 |
| INT-06-12 | MUST | 別resource列・別店舗へdropした場合は変更候補として受理しない。見た目だけ担当先を変えたり、別のresourceを保存先として送信したりしない。 |
| INT-06-13 | MUST | 新規作成の範囲選択は希望枠として扱い、未選択メニューの施術時間や料金を推定して確定しない。メニュー選択後の正式な施術時間・清掃込みの占有が希望枠と異なる場合は、作成画面で実際の終了を示し、既存の作成検証を通す。 |
| INT-06-14 | MUST | 予約の移動・リサイズのドラッグが成立している間、ポインターが時間軸の表示領域の上端・下端へ近づいたら、その時間軸だけを上下へ自動スクロールできるようにする。単なる押下、選択、閲覧スクロール、確認画面の表示だけでは開始しない。 |
| INT-06-15 | MUST | 自動スクロールのたびに、現在のスクロール位置と時間軸の位置から候補座標・候補時刻を再計算する。開始時の座標に固定して候補をずらさない。候補表示と5分単位の時刻判定を同じ計算に合わせる。 |
| INT-06-16 | MUST | 自動スクロールは候補を見渡すための操作とし、スクロール量や端への到達だけでpreview・commit・通知を行わない。有効なpointerup後にINT-09の検証・確認へ進む。 |
| INT-06-17 | MUST | ポインターが端の領域を離れた場合、スクロール限界へ達した場合、pointerupした場合、INT-10のキャンセル条件が成立した場合は自動スクロールを停止し、継続処理を解除する。キャンセル後に画面や候補を動かし続けない。 |
| INT-06-18 | MUST | 初期版では、ドラッグ中に表示期間外へ自動で日送りする機能を必須としない。時間軸の上下端でスクロールを止め、表示期間外への日時変更は同じstore・resourceの日時編集フォームから行えるようにする。 |
| INT-06-19 | SHOULD | 上下端への近さに応じて自動スクロール速度を調整し、急加速を避ける。指・ポインターに隠れない位置で候補時刻を確認できるようにする。 |

## INT-07 タッチでの選択と専用ハンドル

初期版の安定した操作契約は「予約を選択し、指を離した後、専用ハンドルへの次のpointerdownから動かす」とする。長押しした同じ指をそのまま滑らせる方式は、実機検証後に採否を決める拡張候補である。

| 要件ID | 強度 | 仕様 |
| --- | --- | --- |
| INT-07-01 | MUST | タップは詳細表示と選択を行う。詳細を閉じた後も同じ予約の選択を保持し、移動・施術終了変更の専用ハンドルを利用できるようにする。詳細のフォームからも同じ検証・確認・commitで日時を変更できる。 |
| INT-07-02 | MUST | 長押しは予約を選択して専用ハンドルを表示する。長押し成立だけでは予約を動かさず、その指を離すまでは変更ドラッグを開始しない。 |
| INT-07-03 | MUST | 長押しの待機中にスクロール方向の移動が始まったら長押しを取り消す。スクロールが始まった操作を後から予約編集に変換しない。 |
| INT-07-04 | MUST | 選択後、別のpointerdownが専用ハンドルで始まった場合だけタッチの移動・リサイズを開始する。選択中であっても予約カード本体のスライドは閲覧操作として扱う。 |
| INT-07-05 | MUST | 各専用ハンドルの操作領域を最低44×44 CSS pxにする。移動とリサイズの領域を重ねず、短い予約では選択時の補助操作領域を使って確保する。この44pxは本アプリの設計値である。 |
| INT-07-06 | MUST | 移動用と施術終了変更用のハンドルを、見た目とアクセシブルな名前で区別する。清掃帯の高さを調整するハンドルを設けない。選択解除・キャンセルの操作を用意する。 |
| INT-07-07 | MUST | 長押しから同じ指で直接ドラッグする方式を追加する場合、iPhone Safari、Android Chrome、各PWAで縦閲覧・ピンチ・pointercancelとの競合が解消されることを受入条件にする。未検証のまま初期版の必須操作にしない。 |
| INT-07-08 | SHOULD | 詳細内に「カレンダーで移動」のような選択状態へ移る操作を用意し、長押しを知らなくてもハンドルを見つけられるようにする。 |

## INT-08 ブラウザとの入力分担

`touch-action`は操作開始時に評価され、開始後の変更は進行中のジェスチャに反映されない。したがって、長押し成立後に`none`へ変えるだけで、同じ指による縦ドラッグを実現できるとは扱わない。[MDN: touch-action](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/touch-action)

| 要件ID | 強度 | 仕様 |
| --- | --- | --- |
| INT-08-01 | MUST | 独自の横スワイプと標準の縦スクロールを分担する領域では、`touch-action: pan-y pinch-zoom`を候補として、祖先のスクロール要素を含めて実機検証する。 |
| INT-08-02 | MUST | resource列の標準横スクロールを優先する本文では、INT-08-01を一律適用して横スクロールを禁止しない。横・縦・ピンチを許す設定を使用する。 |
| INT-08-03 | MUST | 専用ハンドルのドラッグに必要な`touch-action`は、そのハンドルへのpointerdownより前に適用する。独自操作のために制限する範囲はハンドルに限定する。 |
| INT-08-04 | MUST | カレンダー全体・予約カード全体・ページ全体への`touch-action: none`で閲覧スクロールや拡大を止めない。ハンドルから始まったドラッグ中の追加指は中止として扱い、通常の本文ではピンチ拡大を保つ。 |
| INT-08-05 | MUST | `overscroll-behavior`を使用するときは実際のスクロールコンテナーに適用し、横方向の履歴移動・スクロール連鎖の抑制を実機で確認する。すべてのOSの端操作を無効化できるとは見なさない。 |
| INT-08-06 | MUST | 不要なページ全体の`preventDefault()`を行わない。入力を引き受ける領域とタイミング、wheelのキャンセル可否、リスナーのpassive設定を明示して実装する。 |
| INT-08-07 | MUST | ポインター捕捉を使う場合も、ブラウザがスクロール・ズームとして扱った操作のキャンセルを無視しない。捕捉の解除と状態の後片付けを一度だけ行う。 |

## INT-10 保存しない終了条件

以下は、まだ確定していない独自ジェスチャ・予約変更候補を中止する条件である。予約変更APIを呼ばず、LINE通知を発生させない。

| --- | --- | --- |
| `pointercancel` | 候補・追従表示・押下状態を破棄し、保存済み位置へ戻す。 | INT-10-01 |
| 操作途中の予期しない`lostpointercapture` | 中止する。正常なpointerup後の捕捉解除は二重終了として扱い、既に開いた確認を誤って破棄しない。 | INT-10-02 |

## INT-15 参照資料と確認範囲

一次資料の確認日は2026年11月17日。Googleの一般向けHelpで確認した操作は、月名から開く日付選択の左右スワイプ、空き時間枠のタップ、既存予定のドラッグによる日時移動である。通常の週グリッドの指操作の閾値、長押し時間、Google Calendar Web版のMac横スワイプによる期間移動は、今回の公式資料では確定できなかった。
